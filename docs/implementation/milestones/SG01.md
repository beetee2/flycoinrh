## Candidate

Screen Gremlin is the default; the local Presentation selector retains Legacy.
Jam is original procedural Three.js geometry: a large rounded head, two red
faceted compound eyes, short segmented charcoal abdomen, six jointed legs, two
translucent ivory wings, short antennae, sparse bristles and a subtle proboscis.
Shared geometry and matte materials keep the scene modest. No external assets,
framework replacement, neural/model changes or new physical behavior.

The source image is an aspect-preserving DOM backdrop behind transparent WebGL.
Contain is the default. Synthetic/replay illustrations are original local SVGs
and visibly labeled. Replays explicitly say that their original color backdrop
is unavailable. There is no live-feed pairing with historical trajectories.

World `(x,y,z)` maps rigidly to render `(x,z,-y)`, with one uniform session-origin
subtraction. The root follows the supplied snapshot without clamping. A mostly
fixed three-quarter camera uses a continuous soft dead zone computed from actual
displacement; it has no residual movement after the input pose freezes. Narrow
compositions reserve space for the wings by reducing the effective camera dead
zone and, if needed, increasing camera distance. The distance setting is a
minimum; the dead-zone setting is a maximum. Camera and decorative poses are
repeatable across render schedules. Seeking, reset, session and mode changes
reset presentation history. Heading remains authoritative; banking is bounded
to ±0.045 radians and uses authoritative heading change and playback time.

A softly fading ground patch and height-dependent contact shadow lie on the
actual floor. No grid, cones, horizon or fog in Screen Gremlin. Ground remains
z=-4 with clearance 1.5, v2 collision unchanged; v1 replays remain unconstrained.
Actual mesh tests include pitch, yaw, leg tuck, wings and maximum banking.

The page has explicit source selection/Preview/Start/Stop, synthetic controls,
verified playback, visible state/contact labels, graphics readiness and bounded
Retry. Details and art controls start collapsed. Clean view includes the mark,
plain-text caption (100-character maximum), actual mode/fixture labels, exit and
active Stop. Landscape and portrait are composition previews, not recording or
export features. Strict `screen-gremlin-v1` import/export contains presentation
settings only. No settings are automatically persisted.

## Display boundary

`POST /api/live/sessions/{id}/display` uses the existing owner request,
same-origin CSRF, selected source and active generation. Separate generated
`screen-gremlin-display-1` and `screen-gremlin-display-reply-1` contracts carry
JPEG, frame identity, dimensions and age. SourcePreview and recording schemas
remain unchanged.

The reader reuses the existing full RGB capture reference, not a second capture
or an upscaled thumbnail. Ceiling: 960×540 preserving aspect, 256 KiB JPEG,
15 encodes/second, one cached frame and four in-flight responses. Encoding is
demand driven with no catch-up queue. Client polling waits for each response;
429 lowers delivered rate without releasing ownership. Old/foreign identities,
malformed packets and late responses cannot replace the current backdrop.
Frames older than two seconds are unavailable. Source end/change clears DOM
image URLs and server caches; nothing writes color frames or owner tokens to
settings, storage, recordings or logs.

Display receipt age and frame/session/generation are inspectable independently
of last-inferred input and response identity. This is not exact frame-to-response
synchronization. Display settings and pixels never enter the decoder or neural
encoder. Pillow's existing 12.2.0 pin is now a base dependency for capture-only
JPEG delivery. The image CSP permits only local and Blob images.
